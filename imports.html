Imports

Import a built-in library by name, or bind a source file to a name:

import os
import helpers : "helpers.vp"

Renaming with as

as gives a library or file a different name, as in Python:

import os as system
import helpers : "helpers.vp" as h
import "helpers.vp" as h2

system.Sleep(100)
val total : int = h.add(2, 3)

Once a library is imported under another name, the original name is no longer bound (os.Sleep(1) is an error suggesting system.Sleep(1)). A file can be imported with import name : "file.vp" or with import "file.vp" (the name is the file name without .vp); both forms accept as.

Picking names with from

from os import Sleep, Directory_Exists as exists
from helpers : "helpers.vp" import add, twice as dbl, Point
from os import *

Sleep(100)
val sum : int = add(1, 2)

from X import a, b as c binds only the listed names. from X import * binds every public name (names starting with _ are skipped). A from import does not bind the library or file name itself. Classes, structs, enums and interfaces can also be renamed: from shapes : "shapes.vp" import Point as P makes P a name for Point in types and calls.

Rules that apply to every import:

  • Imports must be at the top level of a file, not inside a function, loop or class.
  • Two imports cannot bind the same name, and a function cannot reuse an imported name.
  • Import paths are resolved relative to the importing file. A file imported twice is compiled once.
  • Circular imports are an error that shows the full chain.

Importing Vamp files

An imported .vp file may contain only func, class, struct, enum and interface declarations, const constants, test blocks and imports. Classes, structs, enums and interfaces keep one global name across all files, so they are used by that name (or imported under another one). Functions and constants are namespaced per file, so add in helpers.vp never clashes with another add. Calls compile to direct calls, and functions that are never called are left out of the program.

import shapes : "shapes.vp"
from shapes : "shapes.vp" import MAX_SIZE as LIMIT

println(shapes.MAX_SIZE)
println(LIMIT)

Packages

A package is a folder of Vamp files inside a vamp_packages folder in the project. vamp install downloads one with git, and it is imported with @ and its name.

vamp install https://github.com/someone/physics physics

import physics : "@physics"                  // vamp_packages/physics/physics.vp
import shapes : "@physics/shapes.vp"         // another file of the package

Vamp looks for vamp_packages in the importing file's folder first, then in each folder above it. vamp packages lists the installed packages and vamp remove name deletes one.

Data files (.vpdata)

A .vpdata file lists the assets a program uses, such as models, textures, fonts, sounds and animations. Use one file per kind of asset, for example Models.vpdata, Textures.vpdata and Animations.vpdata. Each entry starts with object, a name in quotes, and its properties:

object "player" : (
      type : ".obj",
      path : "/objects/player.obj",
      size : (1, 2, 1),
      position : (0, 0, 0),
      scale : 1.5,
      name : "Player"
)

object "tree" : (
      path : "objects/tree.obj"
      scale : 2.0
)
  • path is required. It is relative to the .vpdata file's folder (a leading / has the same meaning), and the file must exist at compile time.
  • type is optional and defaults to the file extension (".obj" above).
  • All other properties are user-defined. A value can be text in quotes, a number, true/false, a group (x, y, z) or a list [a, b, c]. Groups and lists hold one kind of value; if whole numbers and decimals are mixed, all of them become float.
  • Commas between properties are optional. Names follow the same rules as variable names, so code can refer to models.player.
  • // and /* */ comments work as in .vp files.

A data file is imported like a Vamp file. Each object becomes a constant struct with its properties as fields, plus id (its name), type, path and full_path (the absolute path, resolved at compile time):

import models : "Models.vpdata"

println(models.player.path)            // objects/player.obj
println(models.player.scale * 2)       // 3.000000
println(models.player.size)            // (1, 2, 1)

for (entry) in (models.all()) : (       // every object, in file order
    println(entry.id + " " + entry.type)
)
println(models.names())                // ["player", "tree"]

val found = models.get("tree")         // DataEntry?, none if there's no such object
if (found != none) : ( println(found.path) )

all() returns a list[DataEntry] and get returns a DataEntry?. A DataEntry only has the four shared fields (id, type, path, full_path), since objects can have different properties. An object's own properties are read through its name, as in models.player.scale. import "Models.vpdata" binds the name Models, and from models : "Models.vpdata" import player binds player directly.

The data is built into the program, so reading it has no run-time cost. The asset files themselves are not copied into the program. full_path is the file's location on the machine that compiled the program, which is correct during development. A distributed program should open files using path and ship with the same folder layout (the .vpdata file's folder next to the program).

Importing C and C++ libraries

A header or source file is imported like a Vamp file. Vamp asks clang for its declarations, so namespaces, overloads, inline and header-only code all work:

import mathlib : "mathlib.hpp"
from mathlib : "mathlib.hpp" import is_even as even, greet

val area : int = mathlib.area(3, 4)       // geo::area(int, int)
val total : float = mathlib.add(1.5, 2.5) // selects the float overload
println(even(10))
println(greet("Vamp"))
  • Supported extensions: .h .hh .hpp .hxx .c .cc .cpp .cxx.
  • A source file with the same name next to it (mathlib.cpp next to mathlib.hpp) is compiled and linked automatically.
  • To link a prebuilt library, add link "name" after the path: import sdl : "SDL.h" link "SDL2" links -lSDL2. A value with a file extension, such as link "libs/physics.lib", is passed as a file.
  • Namespaces are flattened: geo::area becomes mathlib.area.
  • Overloads are selected by the Vamp types of the arguments, which must match exactly.
  • Type mapping: int ↔ any C integer type (passed as long long, then converted), float ↔ float or double, bool ↔ bool, str ↔ const char * or std::string (a returned std::string is copied into memory that is never freed automatically), plus void returns.
  • Not yet supported: classes and structs, templates, global variables, enums, modifiable references (int &), pointers other than char *, and variadic functions. Attempting to use one produces an error that names it and explains how to wrap it in a plain function.
  • A C++ exception that escapes an imported function prints its message and stops the program.
  • Only functions that are called are compiled in, and each call is a single direct call.

Compiler error messages

Every error starts with file:line:column, shows the source line with a caret, and often ends with a hint:

main.vp:3:25: error: Library 'os' has no method named 'Slep'
  3 | from os import Slep
    |                ^^^^
  hint: did you mean 'Sleep'?

Errors inside an imported file name that file and add note: while importing ... lines showing the chain of imports.
