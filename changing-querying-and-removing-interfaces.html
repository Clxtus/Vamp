Changing, querying, and removing interfaces

Every control created with os.Make_Interface can be changed afterwards. Like the creation call, each function takes the window title and control name as string literals, and the control must belong to a window created by the program.

import os

val window = os.Make_Window("Search")
val status = os.Make_Interface("label", "Search", "status", (
    size = (260, 36),
    position = (20, 20),
    text = "Ready",
    background_color = "#FFFFFF",
    background_transparency = 1.0
))

os.Set_Interface_Text("Search", "status", "Searching...")
os.Set_Interface_Text_Color("Search", "status", "#0e9e86")
os.Set_Interface_Background_Transparency("Search", "status", 0.5)
os.Set_Interface_Position("Search", "status", 20, 60)
println(os.Get_Interface_Width("Search", "status"))
Call Description
os.Get_Interface(window_title, name) Whether the control exists.
os.Set_Interface_Text(window_title, name, text) Replaces a label's or button's text. text can be any string expression.
os.Set_Interface_Visible(window_title, name, visible) Shows or hides the control.
os.Set_Interface_Enabled(window_title, name, enabled) Enables or disables the control. A disabled button no longer reports clicks.
os.Set_Interface_Editable(window_title, name, editable) Allows or blocks typing in a label created with editable = true.
os.Set_Interface_Position(window_title, name, x, y) Moves the control, in pixels from the window's top-left corner.
os.Set_Interface_Size(window_title, name, width, height) Resizes the control. Both values must be positive.
os.Set_Interface_Layer(window_title, name, layer) Changes its layer and reorders it using the same rules as creation.
os.Set_Interface_Text_Color(window_title, name, color) Text color of a label or button; color is a "#RRGGBB" literal.
os.Set_Interface_Background_Color(window_title, name, color) Background color as a "#RRGGBB" literal. Keeps the current transparency.
os.Set_Interface_Background_Transparency(window_title, name, amount) Background opacity from 0.0 (invisible) to 1.0 (solid), same as background_transparency. amount can be a literal or any float or int expression. A literal outside the range is a compile error; a value computed at run time is clamped. A control with no background color yet uses white.
os.Set_Interface_Icon(window_title, name, path) Replaces the image of an icon control or of a button created with icon. The old image is released.
os.Focus_Interface(window_title, name) Moves keyboard focus to the control.
os.Remove_Interface(window_title, name) Destroys the control. Any pending click is discarded. The name stays reserved, so it cannot be created again.
os.Get_Interface_X(window_title, name), os.Get_Interface_Y(window_title, name) The control's position in pixels from the window's top-left corner.
os.Get_Interface_Width(window_title, name), os.Get_Interface_Height(window_title, name) The control's size in pixels.
os.Interface_Visible(window_title, name) Whether the control itself is set to visible.

Functions that change a control return true on success. If the window or control cannot be found they print an error and return false, and the getters return -1.

The following rules are checked at compile time:

  • Each function only accepts the control types it supports: Set_Interface_Text and Set_Interface_Text_Color need a label or button, Set_Interface_Icon needs an icon control or a button made with icon, and Set_Interface_Editable needs an editable label. The check applies even when the call appears before the control's os.Make_Interface.
  • A button made without background_color or background_transparency is a standard Windows button that draws its own colors. To change its text color or background later, create it with a background property.
  • Every control name used in these calls must be created somewhere in the program.

Interface functions identify the window by the title used in os.Make_Interface, so renaming it with os.Set_Window_Title does not affect them. Setting a text color replaces it exactly; the blending from text_transparency is applied only at creation.

Changes are applied on the thread that owns the window, so they are safe to call from a polling loop. Each call sends a single message to the window, and the window handle is cached between calls.
